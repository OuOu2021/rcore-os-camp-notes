## 汇编相关
### Program Counter
* 自动递增，每条指令后自增4
* 不能直接用于逻辑或算数计算，而是通过`jal`，`jalr`，`beq`，`bne`等命令间接修改它来控制程序流
### 寻址模式
* 理解：是指一条命令找到并利用操作数的四种方式，而不仅限于跳转命令。如算数指令的操作数可以来自寄存器、立即数，而从内存的话得先用`ld`等命令加载到寄存器才行
* `RISC-V`指令集的指令为32位长，理论上让跳转以字为单位可以方便扩展跳转范围，但实际上`PC`相对偏移(`jalr`、`jal`)以及条件分支(`bne`)的数值是以2字节(半字)为单位的

#### 立即数寻址
* 如`addi`
* 操作数是指令中的常量
#### 寄存器寻址
* 如`add`，`sub`
* 操作数是寄存器
#### 基址寻址
* 如`ld`，`sd`
* 操作数是指令中的常量+寄存器`offset`

#### PC相对寻址
* 如`jal`，`beq`等程序流控制命令
* 64位的`program counter`与较小的立即数`offset`相加来寻址，方便跳转到当前代码附近的区域，用于函数内的条件分支(`bne`，高级语言`if`语句，`+-2^10`)与无条件跳转(`jalr`，高级语言`循环`语句,`+-2^18`)
* 函数调用可能需要横跨很大范围，`jal`的`20`位立即数也可能不够。这时`lui`与`jalr`两个指令相加，可以跳转到任何`32`位地址：`lui`将地址的高20位写入寄存器，`jalr`将地址的低12位加到临时寄存器并跳转到目标位置。
	* 对于`64`位地址，要进行两次32位加载操作，第一次之后用`slli`左移32位，所以共5条命令

### 链接器
* 通过`ELF`中的重定位信息和符号表来解析标签，并替换为地址
#### 链接器工作流程
1. 将代码和数据模块以符号形式放在内存中
2. 决定数据和指令标签的地址（汇编时标签只是标签，还没有地址）
3. 修正内部与外部引用

### DLL延迟链接
* DLL在第一次调用时才通过动态加载器来进行链接加载，而后续调用则无需再经过动态加载器

### 调用约定
* 寄存器分为保存的和不保存的。这个“保存”与“不保存”是指**在过程内**需不需要保存。保存的由*被调用者*通过保存与恢复，来保证在调用前后不变；而不保存的不是任何时候都不保存，而是不由**被调用者**负责，而是在必要的时候（即：在调用过程后还需要使用 *不保存* 部分的数据）由*调用者*保存与恢复
	* `saved`是由被调用者保证调用前后不变
	* `sp`通过`addi`的压栈弹栈来保证调用前后不变。所以过程的栈帧大小在编译时需要是确定的
	* `fp/s0/x8`也是由调用者维护，在入栈时将原来的`fp`也入栈，然后更新`fp`，在弹栈恢复`sp`前先恢复`fp`
		* 单线程时不涉及存储和恢复栈帧操作，其实只需要`sp`而不需要`fp`也能正常工作。所以`llvm`默认会把`fp`当成一个参数寄存器用，`rusc`可以用`-C force-frame-pointers`编译参数强制维护和使用`fp`。`gcc`好像是相反，默认使用`fp`，通过`-fomit-frame-pointer`来优化掉`fp`
	* `ra`在非叶过程中需要调用者保存
	* `temporary registers`则是调用结束后用不着了，所以无需保证
	* 还有`arg/return registers`也是不保存的，但有可能在调用结束后还用得上，这时就要由调用者来保存，保证在调用后不被覆盖掉

| 保存（调用者需要保证调用前后不变）               | 不保存（调用者无需保证不变）                      |
| ------------------------------- | ----------------------------------- |
| saved registers: x8~x9, x18~x27 | temporary registers: x5~x7, x28~x31 |
| stack pointer: x2(sp)           | arg/return registers: x10~x17       |
| frame pointer: x8(fp)           |                                     |
| return address: x1(ra)          |                                     |
| 栈指针以上的栈                         | 栈指针以下的栈                             |

#### 实例
```rust
#[no_mangle]
#[inline(never)]
pub fn fact(n: i64) -> i64 {
    if n<1 {1}
    else {n*fact(n-1)}
}
```

```asm
fact:
        addi    sp, sp, -16
        sd      ra, 8(sp) 
        sd      s0, 0(sp)
        addi    s0, sp, 16    # 维护sp寄存器
        blez    a0, .LBB0_3
        li      a2, 1
        li      a1, 1
.LBB0_2:
        mv      a3, a0
        addi    a0, a0, -1
        mul     a1, a3, a1
        bltu    a2, a3, .LBB0_2
        j       .LBB0_4
.LBB0_3:
        li      a1, 1
.LBB0_4:
        mv      a0, a1
        ld      ra, 8(sp)
        ld      s0, 0(sp)    # 恢复fp寄存器为sp
        addi    sp, sp, 16
        ret
```

### Assembler Directive
[risc-v汇编语法](https://zhuanlan.zhihu.com/p/588075416z)
* An operation that tells the assembler how to translate a program but does not produce machine instructions; always begins with a period.
* `.section`：定义一个数据段，如`.section .data`
* `.globl`：定义全局符号，之后就可以写在开头:`symbolXXX: `来表示地址了
* `.space`：预留指定大小的空间
* `.align n`：将`PC`推进到`2^n`字节对齐的位置
* `.quad label`：分配并初始化一个或多个64位（8字节）的空间到指定标识的位置
* `sext.w rd, rs`：符号字扩展到64位
* `.incbin`：输入`.bin`地址，插入汇编当中
## rCore Campe ch2 批处理系统
* 批处理系统：多个程序打包到操作系统中，逐个加载到内存中运行
* 在ch2中实际是把应用程序的二进制镜像文件作为数据段链接到内核，然后一个个加载到内存特定区域来运行。实现方式，是靠`build.rs`：生成`link_app.S`，识别有多少个用户程序并一一生成汇编代码标识位置并分配空间
* `os`的`batch`子模块里的`AppManager`全局单例通过`link_app.S`解析出应用的数量以及开头位置

### 特权级
* 实现用户态与系统内核态隔离，防止用户程序破坏操作系统。由硬件和操作系统协同提供，特权级切换的具体过程一部分由硬件直接完成，另一部分则需要由操作系统来实现。
	* ch2中只考虑U特权级用户程序触发Trap，切换到S特权级的批操作系统进行处理
* CSR：用于操作 控制和状态寄存器(Control and Status Registers，CSR)，是一系列寄存器，是特权模式的重要组成部分。CSR指令用于操作CSR寄存器
* 部分与S特权级相关的CSR寄存器（非通用寄存器，不在x0~x31中）：（s系列寄存器其实是m系列寄存器的子集、受限视图）

| CSR 名   | 该 CSR 与 Trap 相关的功能                        |
| ------- | ----------------------------------------- |
| sstatus | `SPP` 等字段给出 Trap 发生之前 CPU 处在哪个特权级（S/U）等信息 |
| sepc    | 当 Trap 是一个异常的时候，记录 Trap 发生之前执行的最后一条指令的地址  |
| scause  | 描述 Trap 的原因                               |
| stval   | 给出 Trap 附加信息                              |
| stvec   | 控制 Trap 处理代码的入口地址                         |

## Trap 用户态到内核态切换
* 硬件自动完成：
	* `sstatus`的`SPP`字段自动修改为当前特权级
	* `sepc`修改为`Trap`处理完成后默认会执行的下一条指令地址
	* `scause`、`stval`修改为Trap原因
	* `CPU`跳转到`stvec`所设置的`trap`处理入口地址执行
* 内核和用户有不同控制流，所以区分了用户栈和系统内核栈
* Trap时需要保留原控制流的寄存器状态到**系统栈**中。系统栈、用户栈都在操作系统`.BSS`段中。切换栈只需要修改`sp`寄存器。
	* 我们不能确定Trap时会调用什么模块，所以只能将寄存器全部保存
	* `sscratch`CSR寄存器存储栈指针，用`csrrw sp, sscratch, sp`对换内核栈与用户栈
